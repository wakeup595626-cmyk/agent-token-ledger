# 自动检测说明

## 检测什么

程序启动和每次刷新都会调用 `default_context`，从当前进程读取：

- `%USERPROFILE%`
- `%APPDATA%`
- `%LOCALAPPDATA%`

然后按这些当前用户目录检查已知智能体工具路径。因此，同一个 EXE 放到不同电脑后，不会复刻开发电脑的用户名和路径，而是检测运行它的当前 Windows 用户。

## 为什么不需要手工配置

支持范围内的来源使用固定目录约定。程序只读检查路径是否存在，再由对应适配器判断是否可以提取 Token。

检测结果分为四种：

| 状态 | 含义 | 处理方式 |
| --- | --- | --- |
| 已发现 | 至少一个已知路径存在，读取正常 | 进入统计 |
| 本机未发现 | 支持该来源，但当前电脑没有已知路径 | 不计入统计 |
| 不支持可靠采集 | 已复核，但数据只有配置、加密内容或没有 Token 字段 | 不猜测、不强行计入 |
| 读取异常 | 路径存在，但适配器读取失败 | 保留错误信息，其他来源继续 |

“本机未发现”不等于统计错误。它说明当前电脑没有该工具的已知账本，或者该工具还没有生成记录。

## 数据真实性

程序读取的是运行它的电脑上真实存在的本机记录，不会使用演示数据，也不会随机生成 Token。费用则由来源实测金额和未采集部分的参考估算组成，不代表云服务商账单原值。详细说明见 [数据真实性与跨电脑读取边界](DATA_AUTHENTICITY.md)。

## 新增来源时如何自动识别

1. 在 `src/agent_token_ledger/sources/` 增加适配器。
2. 在 `pipeline.default_adapters` 注册。
3. 在 `inventory.py` 增加候选路径和状态说明。
4. 给检测、解析和失败隔离增加测试。

新增来源不能依赖开发电脑的固定用户名，也不能把绝对路径写死在界面中。

## 不同电脑的边界

自动检测只覆盖文档中列出的已知格式。第三方软件升级后可能改变目录或数据结构，此时会显示“读取异常”或“不支持可靠采集”。

如果目标电脑没有安装 Microsoft Edge WebView2 Runtime，程序会依次尝试 Edge 应用窗口和默认浏览器。统计和检测逻辑仍然在本机运行。
