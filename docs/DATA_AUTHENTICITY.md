# 数据真实性与跨电脑读取边界

## 结论

发布版只统计运行它的当前 Windows 用户本机日志，不包含演示 Token、随机 Token 或运行时编造的数字。

程序启动和刷新时都会从当前进程读取：

- `%USERPROFILE%`
- `%APPDATA%`
- `%LOCALAPPDATA%`

因此，同一份 EXE 复制到不同电脑后，读取的是那台电脑上的当前用户数据。开发电脑的用户名、绝对路径和本机数据库不会写死到程序中。

## 真实但受条件限制

程序不会凭空补足缺失记录。只有同时满足下列条件，某个来源才会进入统计：

1. 当前电脑安装了对应智能体工具。
2. 该工具已经生成了受支持的日志、导出文件或数据库。
3. 当前工具版本仍使用已实现并测试过的数据格式。

任一条件不满足时，来源页会显示：

- 本机未发现
- 不支持可靠采集
- 读取异常

这三种状态都不会被当成零用量或伪造用量。

## 费用不是云端账单原值

费用统计优先使用来源日志中明确提供的实测金额。对于没有费用字段但已有可核对 Token 的记录，程序会依据已有样本单价做参考估算，并在界面中使用“参考估算”“部分估算”和 `≈` 标识。

所以页面中的总费用口径为：

```text
来源实采金额 + 未采集部分的参考估算
```

它不是云服务商账单原值。人民币费用还会按用户在设置中填写的汇率换算。没有可靠样本时，程序显示“无法估算”，不会把估算值伪装成实际金额。

## 为什么账本总量可能低于代理面板

账本只统计运行它的这台电脑上、当前用户本机生成的日志。如果某一天本机 Codex 原生日志目录里没有对应日期的会话文件，这一天就无法逐请求回算，聚合多终端、多电脑或镜像来源的代理面板数字自然会大于本机账本。统计说明页会列出近 7 天缺失原生日志的具体日期；这些缺口不会用估算 Token 或随机数填补，也不会被当成零用量。

另外，反向代理面板通常统计网关收到的全部请求（可能包含多设备、多账号、镜像与汇总口径），而本机账本只统计本机去重后的原始请求口径，两者天然不是同一个分母。

还要注意时间范围：界面里的“最近 7 天”是按自然日计算（从今天起往前共 7 个日历日，不是滚动 168 小时）。如果上游或反代面板显示的是账号自开通以来的累计总量，而这里只看“最近 7 天”，两者必然对不上；对比累计总量请切换到“全部时间”。这是统计窗口不同，不是漏读来源数据。

## 不会上传或修改来源

程序不上传数据、不登录云端账号、不调用云端模型，也不写入、重命名、移动或删除其他智能体工具的原始数据。

为了加快每次打开和刷新，程序会把解析后的结果缓存到自己的数据目录（属于派生的本地数据），并只在来源文件的大小或修改时间变化时重新解析；来源工具的原始日志始终以只读方式打开，绝不被修改。
